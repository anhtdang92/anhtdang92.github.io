01 Problem

Most stock-prediction demos report accuracy from a random train/test split. On time-series data that leaks the future into training, so the numbers look strong and then fall apart as soon as the model is used forward in time.

ATLAS asks a narrower question: using two years of daily price and volume data, can a model call the direction of a stock's next 21-day return better than simple baselines when it is scored only on later data it never trained on? And can it be packaged so someone else can run it, test it and query it?

02 Approach

  1. Datayfinance: 2 years of daily OHLCV for 33 US stocks and ETFs
  2. Features34 indicators in 30-day lookback windows
  3. Model2-layer LSTM, Huber loss, MC Dropout
  4. EvaluateWalk-forward CV, Optuna, bootstrap CIs, Diebold-Mariano
  5. ServeFastAPI, Vertex AI, Streamlit dashboard
  • Features. 34 technical indicators: moving averages and price-to-MA ratios, RSI, MACD, Bollinger Bands, volume, momentum, volatility and ATR, market-regime signals (volatility regime, distance to 52-week high, z-score, trend strength), sin/cos calendar encodings and relative strength. The scaler is fit on training windows only.
  • Model. A 2-layer LSTM (64 units per layer, 0.2 dropout, L2 regularization) trained with Huber loss to predict the 21-day return. Dropout stays on at inference to estimate uncertainty with Monte Carlo passes.
  • Ablation. Seven architectures under the same walk-forward evaluation: LSTM, BiLSTM + attention, Transformer, CNN-LSTM, a multi-horizon LSTM, XGBoost and Ridge regression.
  • Tuning and statistics. Optuna searches LSTM units, dropout, L2, learning rate and batch size, scoring each trial by mean directional accuracy across walk-forward folds. Bootstrap confidence intervals (10,000 resamples) and Diebold-Mariano tests compare models with the baselines.

03 Key decisions

The repo records three architecture decisions (ADRs), each with the trade-off it accepts.

ADR-001

Huber loss over MSE

WhyReturns are fat-tailed. With MSE, a single earnings gap can dominate a training batch; Huber is quadratic for small errors and linear for large ones.

Trade-offSlightly less sensitive to sub-1% moves, and the delta threshold has to be tuned.

Read ADR-001 on GitHub (opens in a new tab) →
ADR-002

Walk-forward CV over k-fold

WhyRandom k-fold trains on the future and tests on the past. Walk-forward trains on data up to a point in time and scores only the window after it.

Trade-offFewer training samples in early folds and a full retrain per fold, so evaluation costs more.

Read ADR-002 on GitHub (opens in a new tab) →
ADR-003

MC Dropout over model ensembles

WhyPosition sizing needs a confidence score. 50 forward passes with dropout active give a mean and a spread from one model; predictions with confidence below 0.6 are excluded from trade signals.

Trade-offAbout 50× slower inference, and it doesn't capture uncertainty about the architecture itself.

Read ADR-003 on GitHub (opens in a new tab) →

Read plainly: 55–62% directional accuracy is a modest edge over a 50% coin flip, and the Sharpe ranges overlap with buy-and-hold. The clearer gap is drawdown, 8–15% against 15–25%.

Limits (from the model card (opens in a new tab)): one data source (Yahoo Finance price and volume), no fundamentals or macro data, a fixed 21-day horizon, a fixed 33-symbol universe with survivorship bias, and a two-year window that may not cover every market regime. It is an educational and paper-trading project, not financial advice.

05 What I learned

~68%
Random k-fold accuracy (future leaks into training)
55–62%
Walk-forward accuracy (scored only on later data)
  • Walk-forward CV is non-negotiable for time series. Early experiments with random k-fold showed about 68% directional accuracy. Walk-forward dropped it to 55–62%. Lower, but that is the number that reflects real use.
  • Features mattered more than architecture. In the ablation, a simple 2-layer LSTM with good features beat a Transformer with weaker ones, and the market-regime indicators contributed the most.
  • Uncertainty is a filter. Predictions where the MC Dropout passes disagreed were the ones not to trade, which led to confidence-weighted position sizing.
  • Fail loudly. Early versions quietly fell back to mock predictions when no model was trained. That path is gone: the app and the API now return an explicit status instead.
  • Risk controls are part of the product. The 8% stop-loss and 12% drawdown circuit breaker apply regardless of what the model says.

06 Engineering

FastAPI service

POST /api/v1/predict returns a predicted return and confidence per symbol, with an explicit status when no model is available. Also /health, /models, /features and /backtest.

Vertex AI

Training containers and a prediction endpoint on Google Cloud. Serving tries Vertex AI, then the local model, then fails explicitly.

Docker

docker compose up runs the dashboard; an optional profile adds an MLflow tracking server.

Streamlit dashboard

Portfolio, live prices, ML predictions, rebalancing in paper-trading mode, and cloud training progress.

CI and 150+ tests

GitHub Actions runs Black, Flake8, pytest with a coverage gate on Python 3.10 and 3.11, schema checks and a Docker build. Unit and integration tests include a walk-forward backtest.

Model card

Intended use, training data, evaluation method, limitations and ethical considerations, alongside the three ADRs.
